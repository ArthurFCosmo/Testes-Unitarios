## 💠 O que uma assertion faz

Uma assertion é a linha do teste que realmente verifica alguma coisa. Todo o resto do método — criar objetos, chamar o service — é só preparação. A assertion é quem decide se o teste passa ou falha.

Pensa numa receita médica: o médico pede o exame (executa o método), mas é o resultado comparado com o valor de referência que diz se está tudo certo ou não. A assertion é essa comparação.

No JUnit 5, elas ficam no pacote `org.junit.jupiter.api.Assertions` e geralmente são importadas de forma estática, pra poder chamar direto pelo nome:

```Java
import static org.junit.jupiter.api.Assertions.*;
```

---

## 💠 `assertEquals`

Verifica se dois valores são iguais. É a assertion mais usada.

```Java
@Test
void deveCalcularIdadeCorretamente() {
    Integer idadeCalculada = usuarioService.calcularIdade(dataNascimento);

    assertEquals(23, idadeCalculada);
    //            ↑ valor esperado, depois o valor obtido
}
```

O primeiro argumento é sempre o valor **esperado**, o segundo é o valor **obtido** com a execução. Se inverter a ordem, o teste ainda funciona, mas a mensagem de erro fica invertida quando falha — o JUnit relata "esperado: X, mas foi: Y" com base nessa ordem.

---

## 💠 `assertTrue` e `assertFalse`

Verificam se uma expressão booleana é verdadeira ou falsa.

```Java
@Test
void cpfDeveSerValido() {
    boolean resultado = ValidadorCpf.isValido("123.456.789-00");

    assertTrue(resultado);
}
```

---

## 💠 `assertNotNull` e `assertNull`

Verificam se um objeto foi ou não foi retornado.

```Java
@Test
void deveRetornarUsuarioQuandoExiste() {
    Usuario usuario = usuarioService.buscarPorId(1L);

    assertNotNull(usuario);
}
```

Isso é bem comum logo depois de chamar um método que devolve um `Optional` já "desembrulhado", ou qualquer método que possa devolver `null` em algum cenário de erro.

---

## 💠 `assertThrows`

Verifica se um método lança a exceção esperada. É a assertion certa pra testar seus `ElementoNaoEncontradoException` e afins.

```Java
@Test
void deveLancarExcecaoQuandoUsuarioNaoExiste() {
    assertThrows(ElementoNaoEncontradoException.class, () -> {
        usuarioService.buscarPorId(999L);
    });
}
```

Repara na estrutura: o primeiro argumento é a classe da exceção esperada, o segundo é uma lambda contendo o código que **deveria** lançar essa exceção. Se o método rodar sem lançar nada, o teste falha — porque a exceção esperada não aconteceu.

---

## 💠 `assertAll`

Agrupa várias assertions relacionadas, garantindo que **todas** sejam executadas mesmo se uma falhar no meio do caminho.

```Java
@Test
void deveMontarDadosUsuarioCorretamente() {
    DadosUsuario dto = usuarioService.buscarPorId(1L);

    assertAll(
        () -> assertEquals("Arthur", dto.nome()),
        () -> assertEquals("arthur@email.com", dto.email()),
        () -> assertNotNull(dto.idade())
    );
}
```

Sem o `assertAll`, se a primeira `assertEquals` falhasse, o teste pararia ali e você não saberia se as outras duas também estavam erradas. Com `assertAll`, o JUnit roda as três e reporta todas as falhas de uma vez.

| Assertion | Verifica |
|---|---|
| `assertEquals(esperado, obtido)` | Se dois valores são iguais |
| `assertTrue` / `assertFalse` | Se uma expressão booleana é verdadeira/falsa |
| `assertNotNull` / `assertNull` | Se um objeto existe ou não |
| `assertThrows` | Se uma exceção específica é lançada |
| `assertAll` | Agrupa assertions, executa todas mesmo se uma falhar |

---

> 💡 **Resumo:** as assertions são as linhas que realmente validam o resultado do teste — `assertEquals` compara valores, `assertThrows` confere exceções, e `assertAll` agrupa várias verificações sem parar na primeira falha.
