## 💠 O que significa testar uma exceção customizada

As páginas anteriores já testaram exceções sendo lançadas — `assertThrows` apareceu várias vezes cobrindo o `orElseThrow` do `TarefaService`. Essa página cobre uma camada mais específica: quando a **lógica de validação** que decide lançar a exceção está isolada dentro do próprio método, sem depender de um `Repository`.

O exemplo real do SGP é o `converterParaEnumStatus`, do `TarefaService`:

```Java
private StatusTarefa converterParaEnumStatus (String status){
    try {
        return StatusTarefa.valueOf(status.toUpperCase().strip());
    } catch (IllegalArgumentException e) {
        throw new RegraDeNegocioVioladaException("Valor de STATUS inválido. Valores aceitos: PENDENTE, FAZENDO, CONCLUIDA.");
    }
}
```

Não tem mock nenhum envolvido aqui — a exceção nasce de uma regra de negócio pura (o `status` recebido não bate com nenhum valor do enum), não de uma dependência externa.

## 💠 Método privado não se testa direto

Como já vimos na página 8.0, métodos privados não recebem teste próprio — são cobertos através do método público que os chama. `converterParaEnumStatus` é usado dentro de `salvarTarefa`, então é por ali que o teste precisa passar.

```Java
@Test
void deveLancarRegraDeNegocioQuandoStatusInvalido() {

    TarefaRequestDTO requestDTO = new TarefaRequestDTO(
        "Nova tarefa", "Descrição", LocalDate.now(), null, "URGENTE", null, 1L
    );
    // ↑ "URGENTE" não existe no enum StatusTarefa

    Projeto projetoFalso = new Projeto(1L, "Sistema SGP", ...);

    when(projetoRepository.findById(1L)).thenReturn(Optional.of(projetoFalso));

    assertThrows(RegraDeNegocioVioladaException.class, () -> {
        tarefaService.salvarTarefa(requestDTO);
    });
}
```

Repara que o stub de `projetoRepository.findById(1L)` precisa existir, mesmo esse teste não sendo sobre projeto — sem ele, o método lançaria `ElementoNaoEncontradoException` antes de chegar na conversão do status, e o teste falharia pelo motivo errado.

## 💠 Testando a mensagem exata da exceção

Confirmar só a classe da exceção às vezes não é suficiente — duas regras de negócio diferentes podem lançar o mesmo tipo de exceção com mensagens diferentes. Capturar a exceção retornada por `assertThrows` permite validar o conteúdo dela também.

```Java
@Test
void mensagemDeErroDeveInformarValoresAceitos() {

    TarefaRequestDTO requestDTO = new TarefaRequestDTO(
        "Nova tarefa", "Descrição", LocalDate.now(), null, "URGENTE", null, 1L
    );

    when(projetoRepository.findById(1L)).thenReturn(Optional.of(projetoFalso));

    RegraDeNegocioVioladaException excecao = assertThrows(
        RegraDeNegocioVioladaException.class,
        () -> tarefaService.salvarTarefa(requestDTO)
    );

    assertEquals(
        "Valor de STATUS inválido. Valores aceitos: PENDENTE, FAZENDO, CONCLUIDA.",
        excecao.getMessage()
    );
}
```

Isso é especialmente relevante em APIs onde a mensagem da exceção é o que o `GlobalExceptionHandler` devolve pro cliente — a mensagem errada pode passar despercebida se o teste só confere a classe.

## 💠 Cobrindo os valores válidos também

Um teste só do caminho de erro deixa a lógica pela metade. Vale confirmar que os valores aceitos realmente passam sem lançar nada:

```Java
@Test
void deveAceitarStatusValidoSemLancarExcecao() {

    TarefaRequestDTO requestDTO = new TarefaRequestDTO(
        "Nova tarefa", "Descrição", LocalDate.now(), null, "fazendo", null, 1L
    );
    // ↑ minúsculo de propósito — testa o toUpperCase().strip() também

    when(projetoRepository.findById(1L)).thenReturn(Optional.of(projetoFalso));
    when(tarefaRepository.save(any(Tarefa.class))).thenReturn(tarefaSalva);

    assertDoesNotThrow(() -> tarefaService.salvarTarefa(requestDTO));
}
```

`assertDoesNotThrow` é o espelho do `assertThrows` — falha se **qualquer** exceção for lançada dentro do bloco, o que confirma que o caminho feliz continua livre depois da conversão do status.

| Assertion | Cenário |
|---|---|
| `assertThrows(Excecao.class, ...)` | Confirma que a exceção certa é lançada |
| `excecao.getMessage()` | Confirma o conteúdo exato da mensagem |
| `assertDoesNotThrow(...)` | Confirma que nenhuma exceção é lançada no caminho válido |

---

> 💡 **Resumo:** testar uma exceção de regra de negócio isolada passa pelo método público que a contém — `assertThrows` confirma a classe lançada, `getMessage()` confirma o conteúdo exato, e `assertDoesNotThrow` fecha o cenário confirmando que os valores válidos não disparam nada.
