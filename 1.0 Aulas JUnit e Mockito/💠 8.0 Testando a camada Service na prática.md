## 💠 O método testado — `buscarTarefaPorId`

Vamos juntar tudo que foi visto até aqui num teste completo, usando o `TarefaService` real do SGP.

```Java
public TarefaResponseDTO buscarTarefaPorId(Long id) {

    Tarefa tarefa = tarefaRepository.findById(id).orElseThrow(
            () -> new ElementoNaoEncontradoException("Não foi encontrada Tarefa com o Id solicitado.")
    );

    return converterModelParaResponseDTO(tarefa);
}
```

Esse método tem dois caminhos possíveis: encontra a tarefa e devolve o DTO, ou não encontra e lança `ElementoNaoEncontradoException`. Um teste completo cobre os dois.

---

## 💠 Setup da classe de teste

```Java
@ExtendWith(MockitoExtension.class)
class TarefaServiceTest {

    @Mock
    private TarefaRepository tarefaRepository;

    @Mock
    private UsuarioRepository usuarioRepository;

    @Mock
    private ProjetoRepository projetoRepository;

    @InjectMocks
    private TarefaService tarefaService;
}
```

Repara que os três `@Mock` batem exatamente com os três parâmetros do construtor gerado pelo `@RequiredArgsConstructor` do `TarefaService` — é assim que o `@InjectMocks` sabe montar o objeto.

---

## 💠 Caminho feliz — tarefa encontrada

```Java
@Test
void deveBuscarTarefaPorIdComSucesso() {

    Projeto projetoFalso = new Projeto(1L, "Sistema SGP", ...);
    Tarefa tarefaFalsa = new Tarefa(
        1L, "Ajustar layout", "Corrigir alinhamento do menu",
        LocalDate.now(), null, StatusTarefa.FAZENDO, null, projetoFalso
    );

    when(tarefaRepository.findById(1L)).thenReturn(Optional.of(tarefaFalsa));

    TarefaResponseDTO resultado = tarefaService.buscarTarefaPorId(1L);

    assertAll(
        () -> assertNotNull(resultado),
        () -> assertEquals("Ajustar layout", resultado.nome()),
        () -> assertEquals(1L, resultado.projetoId())
    );

    verify(tarefaRepository).findById(1L);
}
```

O stub cria o cenário, a chamada real executa o método, e as duas verificações fecham o teste: `assertAll` confirma o conteúdo do DTO devolvido, e `verify` confirma que o `Repository` foi realmente consultado — não só que o resultado bateu por acaso.

Note que `converterModelParaResponseDTO` é um método privado do `Service` — ele não é testado diretamente, é testado **através** de `buscarTarefaPorId`, já que é chamado internamente por ele. Métodos privados não recebem teste próprio; são cobertos pelos métodos públicos que os usam.

## 💠 Caminho de erro — tarefa não encontrada

```Java
@Test
void deveLancarExcecaoQuandoTarefaNaoExiste() {

    when(tarefaRepository.findById(999L)).thenReturn(Optional.empty());

    ElementoNaoEncontradoException excecao = assertThrows(
        ElementoNaoEncontradoException.class,
        () -> tarefaService.buscarTarefaPorId(999L)
    );

    assertEquals("Não foi encontrada Tarefa com o Id solicitado.", excecao.getMessage());
}
```

Aqui o `assertThrows` também devolve a exceção capturada — dá pra guardar em uma variável e fazer assertions sobre ela, como conferir a mensagem exata. Isso garante que não é só "uma exceção qualquer" sendo lançada, mas a exceção certa, com a mensagem certa.

## 💠 Testando `salvarTarefa` — múltiplas dependências mockadas

```Java
public TarefaResponseDTO salvarTarefa(TarefaRequestDTO tarefa) {

    projetoRepository.findById(tarefa.projetoId()).orElseThrow(
            () -> new ElementoNaoEncontradoException("Não foi encontrado um Projeto com o ProjetoId solicitado.")
    );

    if (Objects.nonNull(tarefa.usuarioResponsavelId())) {
        usuarioRepository.findById(tarefa.usuarioResponsavelId()).orElseThrow(
                () -> new ElementoNaoEncontradoException("Não foi encontrado um UsuárioResponsavel com o Id solicitado.")
        );
    }

    return converterModelParaResponseDTO(tarefaRepository.save(converterRequestDTOparaModel(tarefa)));
}
```

Esse método valida duas dependências (`Projeto` e, opcionalmente, `Usuario`) antes de salvar. O teste precisa mockar os três repositories envolvidos:

```Java
@Test
void deveSalvarTarefaQuandoProjetoEUsuarioExistem() {

    TarefaRequestDTO requestDTO = new TarefaRequestDTO(
        "Nova tarefa", "Descrição", LocalDate.now(), null, "PENDENTE", 5L, 1L
    );

    Projeto projetoFalso = new Projeto(1L, "Sistema SGP", ...);
    Usuario usuarioFalso = new Usuario(5L, "Arthur", ...);
    Tarefa tarefaSalva = new Tarefa(10L, "Nova tarefa", ...);

    when(projetoRepository.findById(1L)).thenReturn(Optional.of(projetoFalso));
    when(usuarioRepository.findById(5L)).thenReturn(Optional.of(usuarioFalso));
    when(tarefaRepository.save(any(Tarefa.class))).thenReturn(tarefaSalva);

    TarefaResponseDTO resultado = tarefaService.salvarTarefa(requestDTO);

    assertNotNull(resultado);
    verify(tarefaRepository).save(any(Tarefa.class));
}
```

Repara no `usuarioResponsavelId` sendo `5L` no DTO de entrada — isso é o que faz o `Objects.nonNull(...)` do método entrar no `if` e chamar `usuarioRepository.findById(5L)`. Se esse stub não fosse configurado, o teste ainda passaria de compilar, mas o mock devolveria `Optional.empty()` por padrão, e o `orElseThrow` lançaria a exceção de usuário não encontrado — quebrando o teste do caminho feliz.

## 💠 Testando a validação que barra o salvamento

```Java
@Test
void naoDeveSalvarTarefaQuandoProjetoNaoExiste() {

    TarefaRequestDTO requestDTO = new TarefaRequestDTO(
        "Nova tarefa", "Descrição", LocalDate.now(), null, "PENDENTE", null, 999L
    );

    when(projetoRepository.findById(999L)).thenReturn(Optional.empty());

    assertThrows(ElementoNaoEncontradoException.class, () -> {
        tarefaService.salvarTarefa(requestDTO);
    });

    verify(tarefaRepository, never()).save(any());
    //                        ↑ confirma que o método parou ANTES de tentar salvar
}
```

Esse último `verify(..., never())` é o mesmo padrão visto na página 7.0 — prova que a validação realmente impediu o fluxo de chegar no `save()`, não só que uma exceção genérica foi lançada em algum lugar do método.

---

> 💡 **Resumo:** um teste de Service completo combina stub (simula o retorno dos repositories), execução do método real, e verificação — via `assertAll`/`assertThrows` no resultado e `verify()` no comportamento — cobrindo tanto o caminho de sucesso quanto os pontos de validação que impedem a execução de continuar.
