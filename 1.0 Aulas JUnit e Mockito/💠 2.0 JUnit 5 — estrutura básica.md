## 💠 Onde ficam os testes

O Maven já reserva uma pasta específica pra isso: `src/test/java`. Ela existe em paralelo à `src/main/java`, com a mesma estrutura de pacotes — se o `TarefaService` está em `src/main/java/.../service`, o teste dele vai em `src/test/java/.../service`.

Isso não é convenção opcional, é o Maven que espera essa estrutura pra rodar os testes automaticamente durante o build.

```
src
├── main
│   └── java/.../service/TarefaService.java
└── test
    └── java/.../service/TarefaServiceTest.java
```

O nome da classe de teste segue o padrão `NomeDaClasse` + `Test` — `TarefaServiceTest`, `UsuarioServiceTest`.

## 💠 A anotação `@Test`

Toda vez que criamos um método de teste, marcamos ele com `@Test`. É essa anotação que diz ao JUnit "isso aqui é um teste, executa ele".

```Java
import org.junit.jupiter.api.Test;

class TarefaServiceTest {

    @Test
    void deveSalvarTarefaComSucesso() {
        // corpo do teste
    }
}
```

Repara no nome do método: `deveSalvarTarefaComSucesso`. Não existe regra rígida de nomenclatura, mas o padrão comum é descrever o comportamento esperado — o nome do método já funciona quase como documentação de qual cenário está sendo testado.

O método não recebe parâmetros e não retorna nada (`void`) — o JUnit só executa o corpo e verifica se alguma assertion falhou.

## 💠 Ciclo de vida — `@BeforeEach` e `@AfterEach`

Em geral, cada teste precisa de um "estado inicial" antes de rodar — por exemplo, uma instância do `Service` com os mocks já configurados. Em vez de repetir esse setup em todo método `@Test`, usamos `@BeforeEach`.

```Java
class TarefaServiceTest {

    private TarefaService tarefaService;

    @BeforeEach
    void setUp() {
        tarefaService = new TarefaService();
        // ↑ roda antes de CADA teste da classe
    }

    @Test
    void deveSalvarTarefaComSucesso() {
        // já pode usar tarefaService aqui
    }

    @Test
    void deveLancarExcecaoQuandoTarefaNaoExiste() {
        // tarefaService foi recriado do zero pra esse teste também
    }
}
```

`@AfterEach` é o oposto — roda depois de cada teste, geralmente pra limpar algum recurso que foi usado. É bem menos comum de usar em testes unitários simples, já que não há conexão de banco ou arquivo aberto pra fechar.

| Anotação | Quando executa |
|---|---|
| `@BeforeEach` | Antes de cada método `@Test` |
| `@AfterEach` | Depois de cada método `@Test` |

Cada teste roda de forma independente — o JUnit recria o estado do zero pra cada um, garantindo que um teste não interfira no resultado do outro.

---

> 💡 **Resumo:** o JUnit 5 organiza os testes em `src/test/java`, marca cada método de teste com `@Test`, e usa `@BeforeEach`/`@AfterEach` pra preparar e limpar o estado antes e depois de cada execução.
